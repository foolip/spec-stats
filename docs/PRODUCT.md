# Product

## Register

product

## Users

WHATWG editors and maintainers first: people who look after one or more
Living Standards and want to know how its maintenance is going (is the PR
backlog growing, where is it). Secondary readers are contributors, browser
engineers and anyone curious, who mostly arrive through a link someone
shared, so every view must make sense on its own.

## Product Purpose

Dashboards about WHATWG spec maintenance, computed in the browser from
public GitHub data (`docs/site-design.md`). Success is an editor answering
a question about a spec's maintenance in a few seconds, and sharing the
exact view with a link.

## Brand Personality

Sober, precise, open. It should read like a well-edited spec: calm,
exact, no hype, every number explained.

## Anti-references

- SaaS analytics dashboards: hero metrics, gradient accents, card grids.
- Leaderboards or anything that ranks or blames people (`docs/plan.md`,
  ground rule 5).
- Gamified stats, streaks, celebratory colour.

## Design Principles

1. **The data first.** Controls are compact and stay out of the way of
   the chart and the tables.
2. **The URL is the view.** Every state can be linked to, and a linked
   view explains itself.
3. **Exact over impressive.** Say what is counted, on which days, from
   which data.
4. **Standard affordances.** Native controls and familiar patterns, the
   same component for the same job everywhere.

## Accessibility & Inclusion

WCAG 2.2 AA (assumed; not yet confirmed with the maintainer): text
contrast, full keyboard use including the charts, screen-reader values for
each chart day, colour-vision-safe series, and light and dark themes.
